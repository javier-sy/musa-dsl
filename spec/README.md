# The test suite

```bash
bundle exec rspec                       # everything
bundle exec rspec spec/series_spec.rb   # one file
```

Most of it is ordinary unit testing. This file is about the part that is not:
the specs that hold the **documentation** to what it claims, and the three
counters that keep them from being quietly relaxed.

## Documentation is executable, and a fence says so

`tools/doc-examples.rb` extracts every fenced block from `docs/` and runs it.
A block fenced ` ```ruby ` is a **promise that the code runs**; a block that
only shows the shape of a solution is fenced ` ```text `, which is why
`docs/idioms.md` is almost entirely `text` — it compares two designs rather
than offering either.

Getting that wrong is the most common way to break the suite while writing
documentation. The error is unmistakable: an example that names a variable the
reader is expected to supply (`control`, `transport`, `on`) fails with
`NameError` and is counted as broken.

```bash
bundle exec ruby tools/doc-examples.rb -v    # what runs, what does not, and why
```

## The three counters

They are the shape of a long clean-up: each one may **only go down**, and each
is asserted from both sides, so lowering the real number without lowering the
constant fails the suite too. That is deliberate — it turns "we should get
round to this" into something that cannot be forgotten, and it means a
constant left too high is caught rather than inherited.

| Constant | Today | What it counts |
|---|---|---|
| `DOCS_BROKEN_CEILING` | 0 | Blocks in `docs/` that declare an output and do not run. Already zero: any new one is a regression. |
| `UNMIGRATED_DOC_SPECS` | 2 | Examples still living in `spec/inline_doc_*` / `spec/docs_*` instead of in the documentation they describe. Counted as examples, not files, so renaming cannot flatter the number. |
| `UNRUNNABLE_CEILING` | 5 | Examples that raise, block, or need a gem this project does not depend on. Counted together because which of the three depends on the machine. |

**When one fails**, read the message before changing the number. Going up is a
regression to fix; going down means the work is done and the constant follows.

**One false alarm to know about.** Every documentation narrative is forked with
a five-second budget, so a loaded machine can kill one that normally finishes.
The signature is the unmigrated and unrunnable counts failing *together, by the
same amount*: that is the machine, not the documentation. `DocExamples::TIMEOUT`
is the knob.

## Vocabulary

`docs/vocabulary.md` is generated by `tools/vocabulary.rb` from the public API,
and `spec/vocabulary_spec.rb` fails when it is stale. Regenerate rather than
edit it:

```bash
bundle exec ruby tools/vocabulary.rb
```
